# MODEL-DISPATCH-RUNTIME-001

## 目标

把现有 Sol/Terra/Luna 文字路由矩阵落实为 Codex 的真实自动派发合同：Sol 主会话负责设计、分级、授权、质量门和最终收口；已授权实现任务按确定性规则以显式模型参数派发给 Terra 或 Luna。

## 验收标准

- 项目 Codex 配置固定 Sol 为主控制模型，并提供 Terra、Luna 执行者与 Terra 只读评审者配置。
- `simple + low` 的已授权实现任务必须派发 `gpt-5.6-luna`；其余已授权实现任务必须派发 `gpt-5.6-terra`。
- 派发必须使用显式模型、推理强度和无历史继承的完整任务包；模型或子代理工具不可用时失败关闭，不允许 Sol 静默代写。
- 父会话记录可审计的真实派发回执；Terra/Luna 不得重新分级、扩大范围或自批完成。
- 本 WorkItem 至少产生一条真实 Luna 派发和一条真实 Terra 派发，并记录父会话工具回执。
- 当前工作区与提交后的干净克隆通过完整 pytest、Ruff、Skill validator、TOML/JSON/JSONL 和 Git 卫生检查。

## 范围

- Codex 项目配置、自定义执行者配置和稳定项目入口。
- Shanforge 模型路由、子代理执行合同、任务简报模板、用户指南和正式工作流设计。
- 模型路由治理测试、独立评审、验证、精确本地提交和干净克隆证据。

## 非目标

- 不新增仓内 `src/` 平台运行时、调度服务、模型 API 封装或新依赖。
- 不声称能够从仓内代码反向读取模型内部身份；真实绑定以父会话显式 spawn 参数和工具成功回执为准。
- 不执行 push、PR、merge、发布、部署或生产动作。

`active`
