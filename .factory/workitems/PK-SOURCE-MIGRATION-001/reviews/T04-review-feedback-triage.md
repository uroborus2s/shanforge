# T04 评审反馈分类与核实

## T04-I1：任务简报覆盖不足

- 反馈来源：task review
- severity：Important
- 反馈要求：覆盖注册路径中既有的中英文、编号标题和无显式任务字段格式。
- 是否清楚：yes
- 是否技术正确：yes
- 证据：当前任务识别依赖中文 `- 任务：` 且要求反引号；章节只接受少量中文精确标题。
  注册目录同时存在 `Task`、`Goal`、`Required Outputs`、`Acceptance Criteria`、
  `1. 目标`、`15. 完成定义` 等稳定格式。
- 是否与用户决策冲突：no
- 是否违反 YAGNI：no
- 处理决定：Fixed。补充确定性标题规范化、英文和编号章节映射、路径内任务实体兜底，
  并以真实注册任务简报建立覆盖测试。

## T04-I2：推测性空态

- 反馈来源：task review
- severity：Important
- 反馈要求：缺事实时不能生成看似真实的目的、工作或交付结果。
- 是否清楚：yes
- 是否技术正确：yes
- 证据：renderer 当前以任务标题拼接三段套话，实施报告和前端设计均规定不猜测。
- 是否与用户决策冲突：no
- 是否违反 YAGNI：no
- 处理决定：Fixed。改成分别说明缺少目的、具体工作、交付结果或完成口径的明确空态。

## T04-I3：正式版本提前生效

- 反馈来源：task review
- severity：Important
- 反馈要求：独立评审和人工确认前不能声明新正式版本已批准发布。
- 是否清楚：yes
- 是否技术正确：yes
- 证据：两份文档控制表已经把新版本写入“正式版本”和“已批准并生效”，发布历史也写入
  T04 增补。
- 是否与用户决策冲突：no
- 是否违反 YAGNI：no
- 处理决定：Fixed。评审期间保留前一正式版本，将本次内容标为同文档候选增补；
  独立复审通过并匹配用户实施授权后才更新正式版本和发布历史。

## T04-R2-I1：局部任务身份只在简报侧限定

- 反馈来源：task rereview
- severity：Important
- 反馈要求：任务简报和 Ledger 必须使用同一个父工作项限定身份，并经过 SQLite 合并为
  一个同时具有最新状态和人类语义的实体。
- 是否清楚：yes
- 是否技术正确：yes
- 证据：复审只读探针得到两个实体，说明单侧改写会拆开状态与说明。
- 是否与用户决策冲突：no
- 是否违反 YAGNI：no
- 处理决定：Fixed。抽取共用 `_qualified_task_id`，Ledger 同时识别 `task` 和
  `task_id`，将 `jsonl-event-v6` 与 `markdown-v3` 统一到同一父工作项限定 ID；
  新增索引级单实体合并回归，并让真实语料测试通过 source registry 枚举且断言 ID 唯一。
