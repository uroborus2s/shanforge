# 任务简报共享 Schema 修复

- 父工作项：`PK-SOURCE-MIGRATION-001`
- 任务：`PK-SOURCE-MIGRATION-001-T04-SCHEMA-REPAIR`
- 状态：`closed`
- 来源：已确认的 T04 最终验证根因

## 目标

让 Registry 登记规则与任务语义解析共用一份字段映射，支持现有任务简报的合理标题、
同行值和缩进列表，同时拒绝真正缺少任务语义的简报。

## 用户角色

项目成员需要从任务简报稳定看到目标、工作、交付、完成条件或验证方式；维护者需要新增
简报在进入索引时即可被回归测试发现。

## 主流程

1. `_TASK_BRIEF_SECTION_KEYS` 成为唯一字段别名表；移除正则中的重复字段白名单。
2. 通用解析器支持 `- 目标：值`、`- 目标：` 后缩进列表，以及 `目的`、`本轮交付`、
   `决策` 等现有别名。
3. 对唯一确实没有任务语义的
   `STATE-RECONCILIATION-001-T01.md` 补一条真实目标，不伪造交付或验证结果。
4. 将任务简报 extractor 从 `markdown-v3` 升级，避免旧缓存贡献被错误复用；同步候选数据
   设计中的 extractor 版本。
5. 用现有失败节点和新增聚焦用例完成 RED→GREEN，再运行完整项目知识回归。

## 异常流程

- 无法映射的字段保持未识别，不用标题或默认成功冒充任务语义。
- 登记简报仍没有任何正式任务语义时，验证失败关闭。
- extractor 版本或候选文档哈希变化后重新冻结，不沿用旧发布哈希。

## 业务规则

- Registry 登记范围与解析 schema 必须可共同验证。
- Ledger 继续拥有状态，task brief 继续拥有人类任务语义。
- 不通过修改四份简报来掩盖共享解析器漂移。

## 安全与权限

- 允许修改：项目知识 extractor、对应测试、任务简报 Registry 版本、候选数据设计、
  `STATE-RECONCILIATION-001-T01.md` 的目标字段、本任务 evidence/report/review/ledger。
- 禁止修改：SQLite schema、生产数据、页面只读边界、其他 Skill、远端 Git、发布和部署。

## 验收标准

1. 现有失败测试从 1 failed 转为全绿，四份简报均提取真实语义。
2. 新测试覆盖别名、空值缩进列表和无语义失败三条根因路径。
3. 项目知识五文件回归、Ruff、Mypy、固定 snapshot 和桌面/390px 浏览器检查通过。
4. 新 extractor 版本使旧贡献失效；两份正式设计在重新验证和确认前保持候选。
5. 独立 reviewer 为 `C0/I0`。

## Baseline 影响

不改变领域、总体架构、数据库表或 API；更新数据设计候选中的 extractor 版本，属于现有
T04 候选的技术元数据修正，后续需要重新确认精确候选哈希。

## 未决问题

需要用户批准本方案后才能修改解析器、测试、Registry 或候选设计。
