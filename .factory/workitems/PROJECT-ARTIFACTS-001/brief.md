# 项目设计与测试资产标准化

## 工作项

- 工作项：`PROJECT-ARTIFACTS-001`
- 中文名称：项目设计与测试资产标准化
- 状态：`implemented_and_independently_approved`
- 发起人：`uroborus`
- 实施者：`AI_EXECUTOR`

## 背景

当前项目已经能够从 Markdown、代码和流水账构建 SQLite 索引与只读 HTML，
但 UX/UI 设计资产、OpenAPI 契约、测试案例、测试结果和测试报告仍缺少统一的
仓库格式、确定性校验、索引关系和面向人的组合展示。设计与文档在 HTML 中还
存在两个入口，无法体现“一份正式文档 + 多个机器附件”的单一事实模型。

## 目标

1. 以 Penpot 作为 UX/UI 可编辑源，仓库保存稳定设计资产合同、Token 和导出资源；
   未连接真实 Penpot 文件时明确显示等待连接，不生成伪造 `.penpot`。
2. 以详细 OpenAPI 3.1 文件作为 HTTP 接口机器合同，并强制中文用途说明、字段说明、
   错误响应、示例和需求/测试追踪。
3. 建立测试案例、单次执行结果和聚合测试报告的版本化机器格式，测试定义与运行证据分离。
4. 将设计文档与普通文档合并为一个“项目文档”入口；同一文档详情组合展示 Markdown
   正文和关联机器附件，继续沿用增量静态 HTML 快照与缓存命中机制。
5. 提供固定 CLI 校验命令，让规则由代码执行，避免每次由 AI 重新判断格式是否合格。

## 非目标

- 不在没有已连接 Penpot 文件的情况下伪造或手工拼装 `.penpot` 二进制包。
- 不实现在线编辑器、服务端动态站点或写操作页面。
- 不替代现有项目需求、设计和测试计划正文；只在原文档中增补稳定资产合同。
- 不提交 SQLite、HTML、运行结果缓存或 Penpot MCP 本机配置。
- 不触碰尚待人工确认的 `PK-SOURCE-MIGRATION-001-T04` 发布门。

## 验收

- `design validate`、`api validate`、`test-cases validate` 可独立运行并输出结构化回执。
- OpenAPI 和测试案例中的每个可执行对象都有稳定 ID、中文说明和追踪关系。
- SQLite 能索引设计资产、API 操作和测试案例，测试案例进入 `pk_test`。
- 项目站点只有一个“项目文档”导航入口，设计文档详情可展示关联机器附件。
- 输入未变化时 HTML 快照命中缓存；输入变化时只重建受影响页面。
- 定向测试、全量相关回归、Ruff、Mypy、锁文件与 diff 检查有新鲜证据。
