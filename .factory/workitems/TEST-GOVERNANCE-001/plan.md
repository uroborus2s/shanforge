# 测试治理整改实施计划

**目标：** 清理旧平台测试引用，统一 Skill 工程的测试案例、运行状态和报告合同，并以可执行测试证明所有正式入口真实存在。

**架构：** 不增加平台运行时或校验器服务；复用现有 Markdown/YAML 事实、pytest 和 Python 标准库，在当前治理测试中增加语义守卫。

**技术栈：** Markdown、YAML、pytest、Ruff、Git。

**工作项：** `TEST-GOVERNANCE-001`

**状态：** `plan_ready`

## 输入与根因

- 用户已批准按已识别差异创建 WorkItem 并实现到干净克隆。
- 直接原因：正式测试计划和 `project-artifacts.testcases.yaml` 引用了已经删除的旧平台测试。
- 根源原因：现有治理测试只检查文本和登记条目，没有验证所引用测试文件是否存在，也没有统一案例状态、批次状态和报告字段。
- fault owner：`test` 与 `design`；风险为 `medium`。

## 范围

- 修正 `docs/06-delivery/test-plan.md` 的当前 Skill-first 测试范围、入口、质量门和结果语义。
- 清理没有当前事实 owner 的旧平台案例目录。
- 增加通用测试案例模板，补齐测试报告模板。
- 明确七种案例结果状态与四种批次验证结论的边界。
- 增强测试治理回归，检查正式测试引用真实存在。
- 形成一套人类可读的 WorkItem 测试报告、独立评审、提交和干净克隆证据。

## 非目标

- 不恢复旧 `src/` 平台、OpenAPI 运行时或相关测试。
- 不新增 schema validator、数据库、服务、依赖或测试框架。
- 不执行远端或生产动作。

## 任务

### T01：当前测试合同与陈旧引用清理

- 先新增失败守卫，证明旧平台路径和不存在入口会被捕获。
- 将正式计划改为当前 Skill-first 测试层级与真实可执行入口。
- 删除没有当前 owner 且全部入口失效的旧平台案例目录。
- 定向验证治理测试与交付流程相邻测试。

### T02：案例与报告模板统一

- 增加一个可复用、面向人的完整测试案例模板。
- 补齐测试报告的身份、追踪、准入准出、七态汇总、未执行原因、环境清理、风险、GO/NO-GO、评审和版本历史。
- 明确 `passed/failed/error/blocked/skipped/not_run/cancelled` 是案例运行结果；`passed/partial/failed/blocked` 是批次验证结论。
- 用同一治理测试锁定模板合同。

### T03：集中质量、评审、提交和干净克隆

- 运行完整 pytest、Ruff、JSON/JSONL、Skill validator 和 diff 卫生检查。
- 修正由本工作项直接触发的当前会话夹具和 Skill 专业前缀哈希。
- 生成一份人类可读测试报告和实现摘要。
- 由未参与实现的 reviewer 做独立只读评审；同范围整改后复验。
- 用 `gitcommitzh` 精确本地提交，再从提交创建干净克隆运行同一验证门。

## 集中质量门

- Red/Green：必须保存能证明陈旧引用守卫真实生效的失败与通过结果。
- 批次评审：`pending`
- 批次验证：`pending`
- 本地提交：用户已要求实现到干净克隆，`authorized`
- 远端：`not_authorized`

## 计划自审

- 规格覆盖：陈旧引用、案例模板、报告模板、状态语义、项目级报告和干净克隆均有任务 owner。
- 允许路径：只覆盖测试治理事实、测试、WorkItem 与必要 memory。
- 可执行性：只使用现有 pytest、Ruff、Git 和 Python 标准库。
- 人工 Gate：没有产品取舍、风险接受或外部动作；独立评审和验证继续执行。
