# TEST-GOVERNANCE-001 实现摘要

## 根因

- 直接原因：正式测试计划和 `project-artifacts.testcases.yaml` 指向已删除的旧平台测试。
- 根源原因：治理测试只检查文本和条目存在，没有解析并验证测试文件路径；案例状态、批次结论和报告字段也没有统一 owner。
- fault owner：`test`、`design`；风险：`medium`。

## 实现

| 范围 | 结果 |
|---|---|
| 正式测试计划 | 改为当前 Skill-first 层级、真实入口、环境和质量门；旧平台入口只作为退役边界说明，不再是执行项 |
| 案例目录 | 删除全部入口失效且无当前 owner 的 `tests/specifications/project-artifacts.testcases.yaml`；可从 Git 历史恢复 |
| 案例模板 | 新增完整的人类可读 `test-cases.md`，覆盖身份、追踪、风险、条件、数据、步骤、预期、入口、证据和清理 |
| 报告模板 | 补齐报告身份、准入准出、七态汇总、环境清理、覆盖、未执行原因、风险、GO/NO-GO、评审批准和版本历史 |
| 状态合同 | 案例使用七态；批次验证使用四态；`partial` 不再被误当成案例结果 |
| 回归守卫 | 自动扫描正式测试计划和案例目录中的 `tests/test_*.py`，任何不存在的入口都会失败 |
| 相邻夹具 | 当前会话测试改为读取会话卡声明的 WorkItem；Skill 冻结哈希更新为本次合同内容 |

## 评审整改

- 送审后并行任务改写同一 Skill，造成工作区候选漂移；本工作项改用精确暂存 hunk 作为评审和提交候选。
- 并行任务的文档布局、迁移、正式设计和测试改动全部排除，本工作项未接管其所有权。
- 隔离候选完整验证为 `236 passed, 4 subtests passed`，Ruff 和 Skill validator 全绿。
