# UI-UX-FULL-EXAMPLE-001：全渠道应用设计与文档样例

## 状态

- 场景：新项目完整样例
- 状态：已由用户授权实施
- 日期：2026-07-24
- 目标读者：产品经理、UX/UI 设计师、客户端/小程序/Web/后端开发者、测试与运维人员

## 目标

以“悦享服务”生活服务预约平台为例，交付一套可直接阅读、可追踪、可复制的完整软件项目样例：

- Android、iOS、微信小程序和响应式管理后台共享同一产品语义。
- Penpot 中包含设计系统、核心用户旅程、平台专属页面和交接说明。
- `docs/` 样例包含入门、用户、开发者和内部项目开发四大模块。
- 需求、设计、API、数据、测试、发布和运维使用稳定 ID 一一关联。
- 样例说明哪些文档必需、哪些按项目类型裁剪，禁止生成空壳文档。

## 样例业务

用户发现生活服务，选择门店、服务人员和时间，确认订单并支付，接收提醒，完成服务后评价；运营人员在管理后台管理服务、门店、订单、退款、营销、权限和审计。

## 范围

- 一个完整 P0 主流程及必要异常/恢复路径。
- 四端平台映射，不追求四端像素完全一致。
- OpenAPI 3.1 契约样例。
- 标准化测试用例、测试结果和测试报告样例。
- 部署、运维、发布和追踪样例。

## 非目标

- 不实现真实客户端、后端或管理后台代码。
- 不穷举商业产品的全部页面。
- 不把样例事实写进 Shanforge 根 `docs/`。
- 不提交 Penpot 账号、Token、SQLite、HTML 缓存或其他运行时文件。

## 验收

1. Penpot 至少包含 6 个语义页面和四端核心流程画板。
2. 样例 `docs/index.md` 能导航到全部正式样例文档。
3. PRD、设计、OpenAPI、测试和追踪矩阵使用稳定 ID 对应。
4. 每份 Markdown 正式样例包含中文版本信息和版本历史。
5. 所有相对链接、OpenAPI YAML、JSON/YAML 机器文件通过校验。
6. `ui-ux-pro-max` skill 能明确定位并使用该样例。
