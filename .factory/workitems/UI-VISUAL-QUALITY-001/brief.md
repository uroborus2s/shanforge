- input_approval: 用户本轮明确要求按照前轮完整方案重构，并增加优秀 UI 美术设计学习。

## 目标和范围

落实前轮八项方案：任务分流、产品视觉方向、候选比较、检索脚本、正式规则保护、跨端映射、素材生产和实际视觉验收方法。增加可追溯案例学习：从原始设计与实际界面观察构图、排版、影像、交互和适用条件，转化为本项目设计依据，避免复制模板。

## 已核实根因与批准改法

- 设计系统分支忽略 stack/json，且默认输出 Web 布局与 GSAP：让上下文显式传入，返回候选资料及适用栈指导。
- 零命中会补 Hero、Inter 和通用蓝色：保留未命中，不生成最终视觉结论；中文关键词转换由 agent 完成，脚本不假装具备翻译能力。
- persist 重写 MASTER 与自动 page overrides：只保存 candidate 文件，不覆盖正式规则和已有页面设计。
- 行业与唯一风格绑定、质量检查偏关键词：解除自动定稿，并补真实 CLI 行为和独立前向检验。
- UI 品牌动画归属冲突：全部 UI 资产归 UI skill，非 UI 独立美术包规则不变。

## 验收

1. 新设计使用产品事实、平台约束、案例学习、差异化方向与实际画面评审；局部和既有批准方向不重做。
2. 候选具有来源、上下文、未决项；unknown/中文零命中不伪造设计。
3. stack/json/max-results 生效；原生端不注入 CSS/GSAP；未指定平台不默认 Web。
4. 持久化和 page 参数不改 MASTER 或 pages 下正式文件，输出路径真实可回读。
5. 组件、SVG、位图、动效各有来源和职责，方向和资源清单确认仍受既有用户授权约束。
6. 定向测试、必要仓库兼容性检查、独立代码与中文评审闭环。12 个 brief 作为可复用设计评估语料交付；本次先重构 skill，真实产品多端截图盲评的未运行范围单独披露，不声称已证明普遍美观。
