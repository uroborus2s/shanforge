# 提示词速查

这些模板用于让 AI 走当前 skill-first 流程。

## 1. 通用模板

```text
项目路径：[项目路径]
当前状态：[你知道的事实]
本轮目标：[一句话目标]
禁止事项：
- 不要散读整仓文档
- 不要跳过评审 / 验证 / 记忆同步
- 不要提交无关改动

请先用 `using-shanforge` 判断当前流程位置；如上下文不足，再用 `project-memory` 恢复最小上下文。
```

## 2. 不确定下一步

```text
项目路径：[项目路径]

我不确定下一步该做什么。
请判断当前阶段、阻塞项、最小需要读取的上下文，以及唯一下一步 skill。
不要直接改文件。
```

## 3. 新项目或历史项目接入

```text
项目路径：[项目路径]
项目状态：[空目录 / 已有代码 / 不确定]
项目目标：[一句话说明]

请先判断项目类型。
如果需要文档治理，使用 `document-templates` 建立或修正最小文档结构。
不要伪造不存在的需求、设计或运行结论。
```

## 4. 需求阶段

```text
项目路径：[项目路径]
本轮目标：补齐需求和验收标准。

请用 `requirements-engineering` 输出可评审的需求结果。
不要直接进入实现。
```

## 5. 设计阶段

```text
项目路径：[项目路径]
需求状态：[已确认 / 仍有缺口]
本轮目标：补齐技术方案。

请先核对必要需求事实，再维护技术选型、架构、模块边界和接口契约。
发现需求缺口时先说明，不要用实现假设补洞。
```

## 6. 执行任务

```text
项目路径：[项目路径]
工作项：[ID 或标题]
本轮目标：[要实现什么]

请按当前 plan 执行最小实现。
完成后同步测试、文档和 `.factory/memory/`，状态只能推进到 `ready_for_review`。
```

## 7. 评审与修改

```text
项目路径：[项目路径]
评审意见：[粘贴 review feedback]

请先核实每条反馈是否成立，再做最小修改。
完成后列出修改、验证和仍需人工确认的事项。
```

## 8. 提交

```text
项目路径：[项目路径]
请使用 `gitcommitzh` 提交当前已确认范围。

提交前先核对 work item、review、verification、memory sync 和暂存范围。
不要提交无关脏改动。
```
