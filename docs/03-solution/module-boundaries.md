# 模块边界文档

**项目名称：** 山海工枢 / shanforge  
**文档状态：** 已确认基线  
**负责人：** 仓库维护者  
**主要读者：** 技术负责人 | 开发 | 测试 | 维护者  
**上游输入：** PRD | 系统架构设计  
**下游输出：** 接口契约 | 任务分解 | 测试设计  
**关联 ID：** `MOD-001` ~ `MOD-004`, `REQ-001` ~ `REQ-006`, `API-001` ~ `API-005`  
**最后更新：** 2026-03-27  

## 1. 模块总览

| 模块 ID | 模块名称 | 目标 | 负责人 |
|---|---|---|---|
| `MOD-001` | 人类文档层 | 提供正式需求、设计、使用和追踪文档 | 文档维护者 |
| `MOD-002` | AI 规则与技能层 | 约束模型行为并提供方法论能力 | 规则维护者 |
| `MOD-003` | 命令与工作流层 | 暴露统一脚本入口并执行阶段动作 | 脚本维护者 |
| `MOD-004` | 项目状态与追踪层 | 管理配置、AI 记忆、工作项和状态合同 | 项目协调者/维护者 |

## 2. 每个模块的边界定义

### `MOD-001` 人类文档层

- 目标：为项目维护者和使用者提供正式可读的事实来源。
- 负责：
  - `docs/README.md`
  - `docs/00-governance/*`
  - `docs/01-discovery/*`
  - `docs/02-requirements/*`
  - `docs/03-solution/*`
  - `docs/08-handover/*`
  - `docs/traceability/*`
- 不负责：
  - 直接执行脚本动作
  - 保存压缩 AI 记忆
  - 替代被管理项目中的 `.factory/`
- 输入来源：用户决策、需求分析、架构设计、脚本/skill 变更。
- 输出对象：人类读者、设计者、协作者。
- 拥有的数据：正式 Markdown 文档。
- 持久化边界：当前仓库文件系统。
- 状态变化：通过单文件演进持续更新。

暴露接口：

| 接口 ID | 类型 | 调用方 | 说明 |
|---|---|---|---|
| `API-005` | Document Contract | 人类读者、维护者 | 正式文档目录和文件结构 |

允许依赖：

- `MOD-002` 提供的协议和规则说明
- `MOD-003` 提供的命令入口事实
- `MOD-004` 提供的配置与状态模型

禁止耦合：

- 不能把 `.factory/memory/*` 直接当正式文档正文
- 不能让任何 `workflows/` 文档继续取代 `docs/` 作为软件工厂项目的正式入口

失败与降级策略：

- 若 AI 记忆或脚本上下文缺失，仍可通过 `docs/` 继续交接和恢复理解。

运维责任：

- 监控项：关键文档是否存在、入口是否可发现、引用是否过期。
- 告警人：仓库维护者。
- 常见故障：文档入口切换后，部分说明仍引用旧路径。

### `MOD-002` AI 规则与技能层

- 目标：规范模型读取顺序、行为约束和专业方法。
- 负责：
  - `AGENTS.md` / `GEMINI.md`
  - `skills/*`
  - 相关运行时协议和角色说明
- 不负责：
  - 直接保存正式项目状态
  - 替代用户指南和产品级正式文档
- 输入来源：项目规则、技能方法、工程纪律。
- 输出对象：模型、协作者。
- 拥有的数据：技能说明、运行时协议、角色说明。
- 持久化边界：当前仓库文件系统。
- 状态变化：随着流程和方法演进更新。

暴露接口：

| 接口 ID | 类型 | 调用方 | 说明 |
|---|---|---|---|
| `API-003` | File Contract | CLI 模型、维护者 | 默认配置和规则入口 |

允许依赖：

- `MOD-001` 的正式文档结论
- `MOD-004` 的项目状态合同

禁止耦合：

- 不应硬编码过期的人类文档入口
- 不应跳过正式需求和设计阶段直接进入实现

失败与降级策略：

- 若某个 skill 缺失，仍应退回到正式文档和基本规则继续工作。

运维责任：

- 监控项：skill 引用有效性、协议路径准确性。
- 告警人：规则维护者。
- 常见故障：技能或脚本仍引用已删除的软件工厂项目 workflow 路径。

### `MOD-003` 命令与工作流层

- 目标：提供统一、可执行的软件工厂动作入口。
- 负责：
  - `factory-dispatch`
  - `factory-agent-session`
  - `factory-command-profiles`
  - `factory-workflow-runner`
  - 其他 `factory-*` 底层脚本
- 不负责：
  - 直接定义产品需求
  - 替代正式文档审批和人类决策
- 输入来源：用户命令、项目路径、当前阶段、配置。
- 输出对象：文档、项目状态、工作项、日志。
- 拥有的数据：命令参数、执行日志、中间结果。
- 持久化边界：脚本自身不长期持久化全部业务事实，主要回写到文档或 `.factory/`。
- 状态变化：随执行动作即时变化。

暴露接口：

| 接口 ID | 类型 | 调用方 | 说明 |
|---|---|---|---|
| `API-001` | CLI Command | 使用者、维护者 | 统一动作分派入口 |
| `API-002` | CLI Command | 使用者、维护者 | 生成会话卡和推荐下一步 |

允许依赖：

- `MOD-002` 提供的规则和技能
- `MOD-004` 的项目状态与配置

禁止耦合：

- 不应要求用户手工记忆全部底层脚本
- 不应绕开正式文档和阶段检查直接写入高风险结果

失败与降级策略：

- 高层入口不可用时，允许退回底层 `factory-*` 命令，但应保留同样的文档同步纪律。

运维责任：

- 监控项：命令可发现性、参数说明、入口一致性。
- 告警人：脚本维护者。
- 常见故障：文档存在，但用户不知道优先使用哪个入口。

### `MOD-004` 项目状态与追踪层

- 目标：为被管理项目提供状态、追踪和 AI 记忆合同。
- 负责：
  - `config/software-factory.defaults.json`
  - 被管理项目中的 `.factory/project.json`
  - `.factory/memory/*`
  - `.factory/workitems/*`
  - 需求追踪关系
- 不负责：
  - 充当人类正式交付文档
  - 替代 `docs/` 中的需求和设计正文
- 输入来源：脚本执行结果、阶段推进、正式文档结论。
- 输出对象：CLI 模型、维护者、阶段检查脚本。
- 拥有的数据：项目阶段、角色、任务、压缩摘要、配置默认值。
- 持久化边界：当前仓库配置文件和被管理项目文件系统。
- 状态变化：随阶段推进和变更同步更新。

暴露接口：

| 接口 ID | 类型 | 调用方 | 说明 |
|---|---|---|---|
| `API-003` | File Contract | 初始化脚本、维护者 | 默认配置合同 |
| `API-004` | File Contract | 被管理项目、脚本、模型 | 项目状态和 AI 记忆合同 |

允许依赖：

- `MOD-001` 的正式文档结论
- `MOD-003` 的执行结果

禁止耦合：

- 不应越权成为正式需求和设计文档的唯一来源
- 不应在没有同步人类文档的情况下单独变化关键事实

失败与降级策略：

- `.factory/` 缺失时，应允许人类回到 `docs/` 和配置重新建立上下文。

运维责任：

- 监控项：阶段状态有效性、文档引用准确性、追踪关系完整性。
- 告警人：项目协调者。
- 常见故障：配置与正式文档入口不一致。

## 3. 跨模块协作规则

- 调用方向：用户先触发 `MOD-003`，再由其协调读取 `MOD-001`、`MOD-002` 和 `MOD-004`。
- 共享数据规则：正式事实优先写入 `MOD-001`，压缩摘要和运行状态再写入 `MOD-004`。
- 事务边界：需求和设计边界变化时，至少同步文档层、规则入口和状态合同。
- 版本兼容约束：只有与专项 skill 绑定的辅助 `workflows/` 文档允许保留；软件工厂项目本身的人类说明文档统一只保留在 `docs/`。
