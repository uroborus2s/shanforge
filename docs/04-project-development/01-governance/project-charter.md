## 1. 项目背景

山海工枢 `v2` 的目标是构建一个高度抽象化的 Agent 平台。平台将 Hermes 的核心思想转化为统一运行时、工作流 DSL、模型策略、能力注册、审批控制和标准响应，让后续业务只需要关注业务本身。

## 2. 项目目标

- 建立统一 Agent Platform Kernel
- 建立 Business Agent App 开发面
- 建立 Workflow DSL 与 step 级模型策略
- 建立 Capability Registry、Approval / Sandbox 与 Evidence 闭环
- 建立可测试、可追踪、可复用的业务装配能力

## 3. 非目标

- 不再以旧命令体系或旧文档治理为产品中心
- 不把远程 SaaS 控制台作为首轮交付前提
- 不要求一次性接入所有模型供应商或业务域

## 4. 成功标准

| 指标 | 目标值 | 度量方式 |
|---|---|---|
| 平台装配能力 | 新业务工作流 1 天内完成首个原型 | Demo Agent App 演练 |
| 模型解耦程度 | 更换 provider 不影响业务 App | 契约测试 |
| 追踪完整度 | REQ / MOD / API / TASK 全部可映射 | 追踪矩阵检查 |
| 响应稳定性 | 所有运行结果可映射到标准 `AgentResponse` | schema 测试 |

## 5. 风险

| 风险 | 缓解措施 |
|---|---|
| 抽象过重 | 先交付最小主闭环与 demo App |
| DSL 设计失衡 | 先做最小 schema，再用示范业务流验证 |
| Provider 边界漂移 | 业务层只允许引用 `model_policy` |
