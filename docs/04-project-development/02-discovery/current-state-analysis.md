# 历史项目现状基线模板

**文档类型：** 模板 / 纳管工作底稿  
**主要读者：** 项目协调者 | 架构师 | 接手协作者  
**负责人：** 历史项目纳管负责人  
**关联 ID：** `REQ-007`, `DOC-LEGACY-BASELINE`  
**最后更新：** 2026-03-27  

## 1. 这份文档什么时候使用

当一个项目已经开发完成、正在运行或已经发布，但从来没有纳入软件工厂时，应先创建这份文档。

它的目标不是重写一份理想化设计，而是把“项目现在真实是什么样”记录清楚，作为后续纳管、Bug 修复和新增需求的事实基线。

## 2. 纳管前的事实优先级

在项目还没有 `AGENTS.md`、`GEMINI.md`、`.factory/` 和阶段化 `docs/` 之前，优先级如下：

1. 当前源码、配置文件和构建方式
2. 当前可运行结果、已发布版本和部署行为
3. 仓库内现有 README、设计文档、接口说明、运维资料
4. 最近变更记录、发布说明、缺陷单、需求单
5. 用户补充的业务背景和维护目标

如果这些信息冲突，以当前真实实现和最新发布结果为准。

## 4. 纳管完成的最小退出标准

- 项目当前真实状态已形成文字化基线
- 已识别当前代码、运行、部署和文档的主要事实来源
- 已识别当前最重要的缺陷、需求或风险
- 已能说明后续应先补文档、先修 Bug，还是先做需求变更

## 5. 常见错误

- 直接相信旧设计文档，而不核对当前代码和运行行为
- 还没建立现状基线，就直接让 AI 开始改代码
- 把未来希望的理想状态写成当前真实状态
- 还没纳管完成，就假设 `.factory/` 中的状态已经存在
