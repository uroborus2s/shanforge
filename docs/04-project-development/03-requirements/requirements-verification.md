## 4. 建议动作

- 继续以 `docs/` 为正式事实来源维护需求和设计。
- 后续任何涉及工作流、脚本入口和用户使用方式的变更，都同步更新 `docs/index.md`、PRD、用户指南和追踪矩阵。
- 对历史项目场景，始终要求 AI 先完成纳管基线，再继续进入 Bug 修复或新增需求流程。
- 相关人类说明文档不再继续保留 `workflows/` 副本，后续维护统一落到 `docs/`。
- 进入下一阶段时，优先补齐管理员指南、发布/运维文档和必要的自动检查。
