# UX/UI 设计文档

## 1. 文档目标

说明当前项目作为 `CLI-first` 软件工厂时，用户真正接触到的体验入口和交互规则。

## 2. 当前体验形态

### 2.1 用户角色与场景

当前主要角色包括：

- 仓库维护者：维护脚本、文档和规则
- 项目协调者：推动需求、设计、测试和发布
- 使用者：在业务项目里调用 `factory-*` 命令
- 文档读者：通过章略·墨衡站点浏览正式文档

### 2.2 关键流程

当前关键旅程不是页面流，而是“文档入口 + CLI 命令入口”：

1. 从 `docs/index.md` 进入对应模块
2. 在用户指南或开发者指南里找到命令和路径
3. 在终端执行 `factory-dispatch`、`factory-agent-session` 或专项命令
4. 回看正式文档和追踪矩阵确认结果

### 2.3 页面与组件

当前“界面”主要由三类组成：

- 文档站点目录页：由 `docs/index.md` 和各级 `index.md` 构成
- CLI 命令输出：用于检查、迁移、初始化和状态诊断
- 仓库文件视图：供维护者直接查看文档、脚本和配置

### 2.4 状态与交互

当前应重点设计的状态包括：

- `--check` 通过 / 异常
- 旧结构待迁移 / 已迁移
- 自定义索引页保留 / 被脚本阻断
- 文档站点可读 / 路径失效

### 2.5 视觉与可访问性

虽然当前没有独立 Web 产品 UI，但文档站点应保持：

- 目录结构清晰
- 章节命名稳定
- 根入口与子入口风格统一
- 适合桌面与移动端阅读

## 3. 当前体验矩阵

| 页面 / 场景 | 用户目标 | 关键组件 | 核心状态 | 设计稿 / 原型 |
|---|---|---|---|---|
| 根文档入口 | 确定阅读路径 | `docs/index.md` | 导航完整 / 缺页 | Markdown 正式页 |
| 用户使用场景 | 找到命令与提示词 | 用户指南、提示词模板 | 可执行 / 不确定下一步 | Markdown 正式页 |
| 开发者接入场景 | 找到函数和接口边界 | 开发者指南 | 入口明确 / 文档缺失 | Markdown 正式页 |
| 历史项目迁移场景 | 判断是否需要迁移 | CLI 检查输出 + 文档说明 | 待迁移 / 已就绪 | CLI + Markdown |
