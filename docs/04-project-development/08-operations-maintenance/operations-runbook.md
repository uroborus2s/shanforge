# 运维手册

## 1. 文档目标

说明当前仓库在日常维护中如何巡检、处理异常和保持共享能力稳定。

## 2. 日常维护项

### 2.1 日常巡检项

每次重要变更后至少检查：

- `tests/` 是否仍全绿
- `docs-stratego source validate` 是否返回 `就绪`
- `docs/` 是否仍保持 4 大模块结构
- 文档里是否存在旧路径或明显占位内容

### 2.2 告警处理

当前没有线上监控告警系统，主要采用“检查失败即人工告警”的方式：

- 测试失败：优先修脚本逻辑
- 文档检查失败：优先看结构、导航、绝对路径污染
- 目标项目迁移失败：优先看路径冲突与链接重写

### 2.3 典型故障

典型故障包括：

- 自定义目录正文被误判异常
- 旧目录迁移后链接失效
- 初始化项目仍生成旧占位模板
- 追踪矩阵和实际文档不一致

### 2.4 升级与恢复

升级后应：

- 先在当前仓库回归
- 再在样例或目标项目验证
- 若发现脚本逻辑缺陷，优先修共享规则而不是仅修单个项目
- 重大问题回退后要在演进文档中补复盘

### 2.5 责任边界

当前责任边界如下：

- 仓库维护者：共享脚本、模板、测试
- 项目维护者：目标项目迁移与本地验证
- 文档维护者：正式页质量和站点入口一致性

## 3. 推荐表格

| 场景 | 现象 | 优先级 | 处理步骤 | 升级对象 |
|---|---|---|---|---|
| 索引检查失败 | `--check` 返回异常 | P1 | 看根导航、子目录入口、绝对路径污染 | 仓库维护者 |
| 迁移失败 | 目标路径冲突或链接错误 | P1 | 看迁移日志、重写路径、必要时回退 | 仓库维护者 |
| 初始化产物过旧 | 新项目仍生成旧模板 | P2 | 检查 `factory-init` 与模板常量 | 仓库维护者 |
| 追踪失真 | 文档与矩阵不一致 | P2 | 更新需求矩阵、接口矩阵和文档索引 | 文档维护者 |
