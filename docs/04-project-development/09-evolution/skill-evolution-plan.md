# Skill 进化方案

## 1. 目标

让 skill 不只是“模板生成器”，而是逐步具备目录识别、变更影响分析、文档联动更新，并把正式校验收口到 `docs-stratego` CLI。

## 2. 进化方向

### 2.1 生成类 skill

负责识别项目类型、生成 4 大模块目录和首批文档骨架。

### 2.2 检查类 skill

负责在需求、接口、函数、发布变化后，检查哪些文档必须更新，阻止“代码变了、文档没变”。

### 2.3 修复类 skill

负责根据 diff 和追踪关系补齐受影响的用户指南、开发者指南、接口说明和内部项目文档。

### 2.4 自校验与学习类 skill

负责比较需求、接口、函数、测试和发布文档之间的一致性，并把常见缺陷沉淀为默认规则。

## 3. 当前优先事项

1. 校验 `brainstorming`、`software-factory-cli` 等相关 skill 与 4 大模块文档路径、最新升级入口和公开/私有分层保持一致。
2. 后续补一个专门的变更影响分析 skill，用于需求 / 接口 / 函数变更后的文档联动更新。
3. 再补“受影响文档自动补齐”能力，把检查和修复闭环打通。

## 4. 分阶段演进方案

### 4.1 第一阶段：模板统一

统一新项目初始化、已有项目接入诊断和文档 skill 使用的目录结构与根导航维护方式。

### 4.2 第二阶段：影响分析

根据需求 diff、OpenAPI diff、函数入口 diff 判断哪些文档必须更新。

### 4.3 第三阶段：自动补文档

在不破坏人工正文的前提下，自动补齐缺失章节、追踪矩阵和发布联动说明。

## 5. 验收标准

- 新项目初始化默认生成 4 大模块结构
- 文档正式流程不再依赖仓内 `factory-docs-*` 旧链路
- 需求、接口、函数变化时，能明确定位必须更新的文档页

## 6. 当前结论

- `document-templates` 已完成 4 大模块单轴结构、根 `docs/index.md` 唯一导航事实源、公开/私有分层和 `docs-stratego` CLI 工作流说明的同步。
- 下一步重点不再是模板目录重构，而是相关 skill 联动校验和变更影响分析能力。
