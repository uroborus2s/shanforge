# 文档协同创作工作流

此技能提供了一个结构化的工作流，用于引导用户进行协作式文档创建。作为一名主动的引导者，你需要带领用户完成三个阶段：背景收集、精炼与结构化、以及读者测试。

## 何时提供此工作流

**触发条件：**
- 用户提到编写文档：“写个文档”、“起草提案”、“创建规范”、“写下来”
- 用户提到特定的文档类型：“PRD”、“设计文档”、“决策文档”、“RFC”
- 用户似乎正在开始一项实质性的写作任务

**初步提议：**
向用户提议使用结构化的协作工作流。解释这三个阶段：

1. **背景收集**：用户提供所有相关的上下文，同时 Claude 提出澄清问题。
2. **精炼与结构化**：通过头脑风暴和编辑，迭代地构建每个章节。
3. **读者测试**：让一个没有任何背景信息的“新鲜” Claude 测试文档，以便在他人阅读前发现盲点。

解释这种方法有助于确保文档在他人阅读时（包括他们将文档粘贴给 Claude 时）能够有效传达信息。询问他们是想尝试此工作流，还是更喜欢自由发挥。

如果用户拒绝，则自由发挥。如果用户接受，则进入第 1 阶段。

## 第 1 阶段：背景收集

**目标：** 缩小用户已知与 Claude 已知之间的差距，以便后续进行智能引导。

### 初始问题

首先向用户询问有关文档的元上下文：

1. 这是什么类型的文档？（例如：技术规范、决策文档、提案）
2. 目标受众是谁？
3. 希望读者读完后产生什么影响？
4. 是否有需要遵循的模板或特定格式？
5. 是否有其他需要了解的约束或背景？

告知他们可以使用速记方式回答，或以任何最适合他们的方式提供信息。

**如果用户提供了模板或提到了文档类型：**
- 询问他们是否有模板文档可以分享。
- 如果他们提供了文件，请读取该文件。

**如果用户提到编辑现有的共享文档：**
- 使用适当的工具读取当前状态。
- 检查是否有不带替代文本（alt-text）的图像。
- 如果存在此类图像，请解释当他人使用 Claude 理解文档时，Claude 将无法看到这些图像。询问是否需要生成替代文本。如果需要，请他们将每张图片粘贴到对话中。

### 信息倾倒 (Info Dumping)

回答完初始问题后，鼓励用户倾倒他们拥有的所有上下文。请求以下信息：
- 项目/背景问题。
- 相关的团队讨论或共享文档。
- 为什么不使用替代方案。
- 组织背景（团队动态、过去的事件、政治因素）。
- 时间线压力或约束。
- 技术架构或依赖关系。
- 利益相关者的顾虑。

建议他们不要担心组织逻辑——先把所有内容都写出来。提供多种提供上下文的方式：
- 自由意识流的信息倾倒。
- 指向要阅读的团队频道或线程。
- 链接到共享文档。

告知他们在完成初步倾倒后，你会提出澄清问题。

**背景收集期间：**
- 当用户提供上下文时，跟踪已学到的内容和仍不清楚的内容。
- 如果用户提到了未知的实体/项目，询问是否应该搜索相关信息。

**提出澄清问题：**
当用户表示已完成初始倾倒（或在提供了大量上下文后），提出澄清问题以确保理解：
根据上下文中的空白点生成 5-10 个带编号的问题。

告知他们可以使用速记方式回答，链接更多文档，或继续倾倒信息。

**退出条件：**
当你的问题显示出对业务的深度理解——即可以针对边界情况和权衡取舍提问，而无需解释基础知识时，表示背景收集已充分。

**过渡：**
询问是否有更多想要提供的背景，或者是否可以开始起草文档。准备就绪后，进入第 2 阶段。

## 第 2 阶段：精炼与结构化

**目标：** 通过头脑风暴、筛选和迭代精炼，逐章构建文档。

**操作说明：**
向用户解释文档将逐章构建。对于每个章节：
1. 询问关于包含内容的澄清问题。
2. 进行 5-20 个选项的头脑风暴。
3. 用户指示保留/删除/合并哪些内容。
4. 起草该章节。
5. 通过外科手术式的编辑进行精炼。

从未知因素最多的章节开始（通常是核心决策/提案），然后完成其余部分。

**章节顺序：**
- 如果文档结构清晰：询问他们想从哪个章节开始。建议从未知因素最多的章节开始。
- 如果用户不知道需要哪些章节：根据文档类型和模板，建议 3-5 个合适的章节。询问此结构是否可行，或是否需要调整。

**结构达成一致后：**
为所有章节创建带有占位符文本的初始文档结构。在工作目录中创建一个 Markdown 文件（例如 `decision-doc.md`）。
告知用户已创建初始结构，现在开始填充每个章节。

**针对每个章节：**

### 步骤 1：澄清问题
宣布开始编写 [章节名称]。提出 5-10 个关于应包含内容的澄清问题。告知他们可以使用速记回答。

### 步骤 2：头脑风暴
根据章节的复杂程度，为该章节构思 [5-20] 个可能包含的内容点。重点关注：
- 可能被遗忘的已分享背景。
- 尚未提及的角度或考虑因素。

生成 5-20 个带编号的选项。

### 步骤 3：筛选
询问应保留、删除或合并哪些点。请求简短的理由，以帮助学习后续章节的优先级。

### 步骤 4：空白检查
根据所选内容，询问 [章节名称] 是否遗漏了任何重要内容。

### 步骤 5：起草
根据所选内容起草该章节。
告知用户已根据选择起草了 [章节名称]。请他们阅读并指出需要修改的地方。强调具体的修改意见有助于学习他们的风格。

**首个章节起草时的关键指令：**
提供一个注释：请不要直接编辑文档，而是指示需要更改的内容。这有助于学习他们在未来章节中的风格。例如：“删除 X 列表项——已经在 Y 中涵盖了”或“让第三段更简洁”。

### 步骤 6：迭代精炼
根据用户反馈：
- 使用文本替换工具进行编辑（严禁重新打印整个文档）。
- 继续迭代，直到用户对该章节满意。

### 质量检查
在连续 3 次迭代且无实质性更改后，询问是否可以删除任何内容而不丢失重要信息。
完成后，确认 [章节名称] 已完成，并询问是否准备好进入下一章。

**对所有章节重复上述过程。**

### 接近完成
当 80% 以上的章节完成时，宣布将通读整个文档并检查：
- 章节间的连贯性和一致性。
- 冗余或矛盾。
- 是否有任何“废话”或通用的填充内容。
- 每句话是否都有其价值。

阅读整个文档并提供反馈。

**所有章节起草并精炼后：**
宣布所有章节均已起草。回顾整体的一致性、流畅性和完整性。提供最终建议。询问是否准备好进入“读者测试”。

## 第 3 阶段：读者测试

**目标：** 用一个“新鲜”的 Claude（无上下文干扰）测试文档，以验证其对读者的有效性。

**操作说明：**
解释现在将进行测试，以查看文档是否真正对读者有效。这可以捕捉到作者认为理所当然但可能令他人困惑的盲点。

### 测试方法

用户需要手动进行测试：

1. **预测读者问题**：询问人们在发现此文档时可能会问什么问题。生成 5-10 个读者会真实提出的问题。
2. **设置测试**：
   - 打开一个新的 Claude 对话。
   - 粘贴文档内容。
   - 向“读者 Claude”提出生成的问题。
3. **运行额外检查**：
   询问读者 Claude：
   - “这份文档中有什么对读者来说可能是模糊或不清楚的？”
   - “这份文档假设读者已经具备了哪些知识或背景？”
   - “是否存在任何内部矛盾或不一致之处？”
4. **根据结果进行迭代**：询问用户读者 Claude 在哪些方面出错了或遇到了困难。返回精炼阶段修复这些差距。

### 退出条件
当读者 Claude 能够持续正确回答问题，且不再暴露出新的空白或模糊点时，文档即告完成。

## 最终审查

当读者测试通过后：
1. 建议用户自己进行最后一次通读——他们拥有这份文档并对其质量负责。
2. 建议再次检查事实、链接或技术细节。
3. 询问他们是否达到了预期的影响。

确认完成后，宣布文档创作结束。

## 有效引导技巧

- **语调**：直接、程序化。简要解释影响用户行为的基本逻辑。不要试图“推销”此方法——只需执行。
- **处理偏差**：如果用户想跳过某个阶段，询问他们是否想直接自由写作。
- **上下文管理**：如果提到的内容缺乏上下文，主动提问。不要让差距积累。
- **质量重于速度**：不要匆忙。每次迭代都应带来有意义的改进。
