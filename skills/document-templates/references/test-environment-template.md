# 测试环境与追踪模板

只在项目存在可重复测试、服务启动或正式发布验证时使用本模板。没有对应测试层级时写 `N/A` 和原因，不创建空文档，也不保留含糊占位。

## 1. 环境契约

| 字段 | 内容 |
|---|---|
| 环境 ID | `<TEST-ENV-ID>` |
| 适用性 | `<适用范围；不适用时写 N/A 和原因>` |
| 运行位置 | `<本地 / CI / 隔离测试环境>` |
| 准备命令 | `<依赖与夹具准备命令>` |
| 启动命令 | `<完整、可复制命令；无独立进程时写 N/A 和原因>` |
| 端口 | `<固定或动态实际端口；无监听端口时写 N/A 和原因>` |
| 健康检查 | `<命令、URL 或静态文件/DOM 检查>` |
| 就绪条件 | `<可开始测试的可观察条件>` |
| 关闭方式 | `<关闭命令或进程托管方式；无独立进程时写 N/A 和原因>` |

| 负责人 | `<owner>` |

## 2. 测试追踪

正式测试使用稳定 `TEST-*` ID。同一测试的多次运行只新增 evidence，不新建测试定义。

| TEST-* | 名称 | 需求 ID | 任务 ID | 层级 | 命令 / 入口 | 证据 | 结果 |
|---|---|---|---|---|---|---|---|
| `<TEST-ID>` | `<人类可读名称>` | `<REQ-ID>` | `<TASK-ID>` | `<单元 / 黑盒 / UI / API / 发布回归>` | `<命令或 URL>` | `<evidence path>` | `<passed / failed / error / blocked / skipped / not_run / cancelled>` |

## 3. 发布回归

- 发布影响：`<有 / 无；无时写 N/A 和原因>`
- 回归入口：`<TEST-RELEASE-* 与命令>`
- 失败处理：`<阻断、回滚或修复路径>`
- 未运行项：`<none 或明确项目及原因>`

## 4. 完成检查

- 启动命令、端口、健康检查和关闭方式均有明确值或带原因的 `N/A`。
- 每个测试可从需求追到任务、测试定义和本轮 evidence。
- failed、error、blocked、skipped、not_run、cancelled 与未覆盖风险均显式记录。
- 测试结束已关闭进程并清理临时产物。
