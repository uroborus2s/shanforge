# 追踪规则与阶段关口

## 每份正式文档的最小元数据

建议每份正式文档开头至少写明：

- 项目名称
- 文档状态：草稿 | 评审中 | 已批准 | 已发布 | 已废弃
- 负责人
- 主要读者
- 上游输入
- 下游输出
- 关联追踪 ID
- 最后更新时间

这组元数据的目的，是让接手人能快速判断“这份文档现在能不能用、该和谁确认、看完之后该去哪里”。

## 推荐追踪 ID 体系

| 前缀 | 含义 |
|---|---|
| `BIZ-xxx` | 业务目标或商业诉求 |
| `RISK-xxx` | 风险项 |
| `REQ-xxx` | 功能需求 |
| `NFR-xxx` | 非功能需求 |
| `UX-xxx` | 用户旅程、页面或交互规格 |
| `ADR-xxx` | 架构决策记录 |
| `MOD-xxx` | 模块或组件边界 |
| `API-xxx` | API 端点或接口 |
| `EVT-xxx` | 事件契约 |
| `INT-xxx` | 内部接口或集成项 |
| `DATA-xxx` | 数据实体、表或迁移项 |
| `SEC-xxx` | 安全控制点 |
| `DEP-xxx` | 部署或环境项 |
| `TASK-xxx` | 实施任务 |
| `TC-xxx` | 测试用例 |
| `UAT-xxx` | 验收项 |
| `REL-xxx` | 发布项 |
| `OPS-xxx` | 运维操作项 |
| `DOC-xxx` | 用户/管理员/支持文档项 |
| `CR-xxx` | 变更请求 |
| `INC-xxx` | 事故或问题项 |

规则：

- 同一项目内按前缀分别递增。
- 废弃的编号不回收。
- 文档中尽量引用编号，而不是只写自然语言标题。

## 追踪矩阵最少要覆盖什么

最小矩阵至少能回答以下关系：

- `REQ/NFR -> MOD/API/DATA`
- `REQ/NFR -> TASK`
- `REQ/NFR -> TC/UAT`
- `REQ/NFR -> 发布状态`
- `MOD/API -> 运维责任`

如果项目存在跨团队接口，再额外维护：

- `接口 -> 提供方/消费方`
- `接口 -> 版本/兼容策略`
- `接口 -> 监控与告警`

## 阶段关口

### 立项 -> 需求

至少准备：

- 项目章程
- RACI / Stakeholder
- 风险登记册

通过标准：

- 目标、范围、负责人、成功标准已经明确
- 已知高风险点已记录

### 需求 -> 方案设计

至少准备：

- PRD
- 需求分析
- NFR 目录
- 验收标准

通过标准：

- 需求优先级明确
- 非功能要求可被设计与测试引用
- 变更入口清晰

### 方案设计 -> 开发实施

至少准备：

- 系统架构设计
- 模块边界文档
- 接口契约文档
- 数据设计
- 实施计划

通过标准：

- 模块职责和依赖方向明确
- 接口语义、输入输出、错误与兼容策略明确
- 可以据此拆任务、写代码、写测试

### 开发实施 -> 测试/验收

至少准备：

- 测试策略或测试计划
- 关键测试用例
- 可追踪到需求的任务状态

通过标准：

- 每个高优先级需求都有验证路径
- 已知风险有专门测试覆盖

### 测试/验收 -> 发布

至少准备：

- 测试报告
- 缺陷清单
- UAT 结果（需要时）
- 发布检查清单
- 回滚方案

通过标准：

- 残留问题被明确接受或关闭
- 上线失败时有可执行回退路径

### 发布 -> 运维/交接

至少准备：

- 发布说明
- 部署说明
- 运维手册
- 用户指南
- 管理员指南（如有管理员角色）

通过标准：

- 接手团队能独立完成部署、巡检、基础故障排查
- 用户或实施方知道如何完成主要操作

## 最小文档包建议

### 小型内部工具

至少保留：

- 项目章程
- PRD
- 系统架构
- 模块边界
- 实施计划
- 测试计划
- 部署说明
- 用户指南

### 标准业务系统

至少保留：

- 小型内部工具全部内容
- 接口契约文档
- 发布检查清单
- 回滚方案
- 运维手册
- 管理员指南
- 追踪矩阵

### 集成型或平台型系统

额外补齐：

- 集成清单
- API/Event 契约文件
- 配置矩阵
- 监控告警说明
- 支持手册

### 高风险、金融、医疗、关键基础设施类系统

额外补齐：

- 安全设计 / Threat Model
- 备份与灾备方案
- 生产就绪评审
- 审计或合规映射
- 事故预案与复盘机制

## 推荐写法

- 把文档写成“下一个人拿到就能继续工作”的形式。
- 把阶段关口写成“缺哪份文档就不能稳妥交接”的形式。
- 把追踪矩阵写成“可以快速检查遗漏”的形式，而不是装饰性表格。
