# 中文提交模板

这份参考文档用于帮助 `gitcommitzh` 生成更稳定的中文提交标题和正文。

## 1. 标题模板

默认格式：

```text
<type>: <中文简短标题>
```

推荐类型：

- `feat`: 新增能力、入口、功能或自动化
- `fix`: 修复错误、边界、回归或错误行为
- `refactor`: 重构实现但不改变对外行为
- `docs`: 只改文档、说明、模板、索引或注释
- `test`: 新增或修正测试、验证脚本、回归用例
- `chore`: 工具链、脚本、配置、链接同步、清理类改动

## 2. 标题示例

- `feat: 增加 Git 中文提交 skill`
- `fix: 修正历史项目纳管文档的人机入口边界`
- `refactor: 收敛 intent 解析的技能生命周期路由`
- `docs: 更新全局 skills 同步说明到三端目录`
- `test: 补充 sync-codex-skills 的 dry-run 验证`
- `chore: 同步共享 skills 到 codex gemini agents`

## 3. 正文模板

推荐使用三段式正文：

```text
背景：
- 为什么需要这次提交

主要改动：
- 改了哪些文件或模块
- 行为上有哪些变化

验证：
- 执行了什么验证
- 如果未验证，要明确写未执行
```

## 4. 正文示例

```text
背景：
- 新增一个专门处理 Git 中文结构化提交的共享 skill。
- 现有全局 skills 同步脚本只覆盖 Codex 和 Gemini，未覆盖 agents。

主要改动：
- 新增 gitcommitzh skill 与中文提交模板参考文档。
- 扩展 sync-codex-skills，支持同步到 ~/.agents/skills。
- 更新用户文档和接口文档中的同步范围说明。

验证：
- 运行 py_compile 校验脚本语法。
- 使用 dry-run 验证三端同步输出。
```

## 5. 选词建议

- 优先使用“新增、修正、补齐、收敛、同步、拆分、抽离、限制、校验、刷新”。
- 优先描述结果，不要堆抽象形容词。
- 标题尽量只写一个主动作，不要把三四件并列事项硬塞进一行。

## 6. 反例

不推荐：

- `update`
- `fix bug`
- `修改一些东西`
- `提交改动`
- `feat: 更新文档并修复脚本并补测试并同步链接`

这些标题的问题通常是：

- 动作太泛
- 范围不清
- 无法快速扫读
- 把多个主题混成一个提交
