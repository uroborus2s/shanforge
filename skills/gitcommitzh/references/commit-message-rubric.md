# 中文提交说明评审标准

用于生成或审查中文 commit message。

## 必须包含

### 提交范围

- 纳入哪些文件。
- 排除哪些文件。
- 是否存在未暂存或未追踪改动。
- 为什么这些文件属于同一个任务。

### 变更概览

- 2-5 条中文完整句。
- 说明变更类型：`feat`、`fix`、`refactor`、`docs`、`test`、`chore`。
- 说明用户或维护者能观察到的变化。

### 详细改动

- 按主题或文件分组。
- 每组说明改了什么、为什么改、影响是什么。

### 风险与影响

- 是否影响接口、行为、配置、脚本、文档、测试。
- 是否存在未完成 review、未闭环 PR 或未同步 memory。
- 是否包含用户已有改动。

### 验证情况

- 只写真实执行过的命令和真实结果。
- 未执行的检查必须写“未执行”和原因。

## 禁止

- 禁止把无关改动混入同一提交。
- 禁止用“更新文件”“修复问题”这类空标题。
- 禁止声称未运行的测试已经通过。
- 禁止提交信息和实际 `git commit` message 不一致。
- 禁止在未核查 diff 时生成最终提交。

## 推荐格式

```text
<type>: <中文简短标题>

背景：
- <为什么需要这次变更>

主要改动：
- <改动 1>
- <改动 2>

验证：
- <命令>：<真实结果>
```
