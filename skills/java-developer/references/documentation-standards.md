# Java 开发文档规范

文档只写会被使用的内容。不要把代码规范、API 说明、部署说明和设计决策混在一页里。

## 文档类型

| 类型 | 适用场景 | 必须包含 |
|---|---|---|
| README | 模块或服务入口 | 用途、启动、测试、配置入口 |
| API 说明 | 接口对外或跨团队使用 | 路径、方法、请求、响应、错误码、示例 |
| 开发说明 | 维护者需要理解实现 | 分层、核心流程、事务边界、外部依赖 |
| 变更记录 | 行为、配置、接口或数据结构变化 | 变更点、兼容性、迁移动作、验证命令 |
| Review 记录 | 评审或交付前 | 问题、风险、结论、未决项 |

## 写作规则

- 先确认读者：使用者、调用方、维护者、运维或 reviewer。
- 只写当前真实行为，不写未来计划。
- 示例命令必须能在项目里执行，不能编造。
- 配置说明必须列出来源：`application.yml`、环境变量、配置中心或 Secret。
- API 文档必须和 DTO、校验和错误响应一致。
- Bug 修复文档必须写根因和验证，不写“已兼容”这种空话。
- 重构文档必须说明行为不变和验证方式。
- 安全、认证、权限、事务和数据迁移必须写风险和回滚条件。

## 禁止

- 禁止写没有事实来源的教程式长文。
- 禁止把临时计划写成已完成事实。
- 禁止把未验证命令写成可用命令。
- 禁止把内部实现细节暴露到公开 API 文档，除非用户明确要求。
- 禁止复制代码注释当文档；文档要说明如何使用和维护。

## 文档 Review Checklist

- 文档是否对应当前代码和配置。
- 是否说明目标读者和适用范围。
- 是否有启动、测试或调用示例。
- 是否列出错误响应、权限、事务或数据影响。
- 是否说明兼容性、迁移和回滚。
- 是否遗漏相关代码变更的文档更新。
