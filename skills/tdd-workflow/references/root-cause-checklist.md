# Bug 根因定位清单

修 Bug 前使用。目标是先定位真实原因，再改最小代码。

## 根因记录

```text
Bug 症状：
复现步骤：
失败证据：
受影响路径：
直接原因：
根源原因：
修复点：
防回归测试：
是否涉及兜底/降级：是/否；如果是，说明它为什么是既有契约。
```

## 必做

1. 先复现失败。
2. 记录真实错误、日志、断言或用户可见症状。
3. 找到直接原因：哪一行、哪个分支、哪个契约破坏。
4. 找到根源原因：为什么当前系统允许它发生。
5. 新增或修改测试，锁定根因路径。
6. 再修改实现。
7. 再运行定向测试和相关回归。

## 禁止

- 禁止用未验证兜底替代根因修复。
- 禁止用宽泛 `except Exception` 掩盖错误。
- 禁止返回空集合、默认成功、静默跳过来让测试变绿。
- 禁止只修用户提到的入口而不检查共享调用点。
- 禁止没有失败证据就声明已修复。

## 输出

把根因记录写入 bug report、work item evidence 或提交说明。没有根因时，只能提交诊断或复现测试。
