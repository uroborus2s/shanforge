# TDD、调试和验证门

用于把测试先行、根因定位和完成前验证合成同一条质量门。

## 新功能

1. 先写测试。
2. 先看测试失败，再写实现。
3. 失败原因必须符合预期。
4. 最小实现让测试通过。
5. 保持相关回归通过。
6. 完成声明前必须有新鲜验证证据。

## Bug 修复

1. 修 Bug 时先写根因记录。
2. 先复现问题。
3. 找到直接原因和根源原因。
4. 写失败测试、复现脚本或验收用例。
5. 只修根因路径。
6. 运行定向测试和相关回归。
7. 把验证证据写入 work item evidence。

## 禁止

- 禁止测试后补。
- 禁止测试立即通过还继续实现。
- 禁止用兜底替代根因修复。
- 禁止把未运行的验证写成通过。
- 禁止把旧验证结果当作本轮证据。
