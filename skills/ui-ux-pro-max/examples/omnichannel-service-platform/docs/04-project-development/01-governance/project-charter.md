## 项目目标

在四个客户端入口中提供一致的预约结果，并尊重各平台导航、权限、支付和无障碍习惯；让运营团队能安全处理服务、订单和退款。

## 范围

- 消费者：服务发现、详情、预约、支付、订单、取消退款、评价。
- 运营：指标、订单、服务价格、角色权限、审计。
- 平台：iOS、Android、微信小程序、响应式管理后台。

## 里程碑

| 里程碑 | 退出条件 |
|---|---|
| M1 需求基线 | P0 REQ/AC/NFR 可测试 |
| M2 设计基线 | 四端主流程、API、数据和异常恢复可实现 |
| M3 集成测试 | P0 契约、真机和管理后台关键路径有证据 |
| M4 灰度发布 | 回滚、监控、隐私与支付对账通过 |

## 主要风险

| 风险 | 处置 |
|---|---|
| 支付回跳和回调乱序 | 服务端状态机、幂等、对账和恢复查询 |
| 时段并发超卖 | 下单二次校验、短锁和冲突提示 |
| 跨端视觉复制导致平台体验错误 | 共享语义，不共享平台导航实现 |
| 客服越权查看隐私 | 默认脱敏、额外授权、全量审计 |
| 小程序包体和宿主限制 | 分包、原生能力矩阵、真机验证 |
