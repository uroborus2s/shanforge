## 产品目标

让用户在任一消费者端完成一次确定、透明、可恢复的服务预约；让运营人员在受控权限下完成订单、退款和服务管理。

## 用户与用户故事

| 用户 | 用户故事 |
|---|---|
| 消费者 | 作为消费者，我希望比较服务、价格、人员和时间，以便放心预约。 |
| 消费者 | 作为支付中断的用户，我希望恢复订单状态，而不是重复付款。 |
| 客服 | 作为客服，我希望快速查看脱敏订单和履约事件，以便解释和处理问题。 |
| 运营 | 作为运营，我希望维护服务和未来价格，但不改变历史订单。 |
| 管理员 | 作为管理员，我希望高风险操作有权限和审计记录。 |

## 功能需求与验收标准

### `REQ-CATALOG-001` 服务发现

用户能按城市、分类和关键词查看当前可售服务。

- `AC-CATALOG-001-01`：只展示当前渠道和区域可售的服务。
- `AC-CATALOG-001-02`：无结果时解释原因并提供清除筛选或切换城市。
- `AC-CATALOG-001-03`：网络失败保留搜索条件并提供重试。

### `REQ-CATALOG-002` 服务详情

用户下单前能理解服务内容、时长、价格起点、人员资质、取消政策和风险提示。

- `AC-CATALOG-002-01`：价格不是固定价时必须显示“起”并解释影响因素。
- `AC-CATALOG-002-02`：服务说明、禁忌和取消政策可被屏幕阅读器完整读取。

### `REQ-BOOKING-001` 选择人员与时间

用户能选择可用人员、日期和时间，库存过期时得到明确恢复路径。

- `AC-BOOKING-001-01`：不可用时段不可提交但仍说明不可用原因。
- `AC-BOOKING-001-02`：创建订单时再次校验库存，冲突返回新的可选时间。
- `AC-BOOKING-001-03`：拒绝定位后允许手动选择地址。

### `REQ-ORDER-001` 创建预约订单

系统以价格快照和取消政策快照创建待支付订单。

- `AC-ORDER-001-01`：同一幂等键重复提交返回同一订单。
- `AC-ORDER-001-02`：订单保存服务、人员、时间、地址引用、成交价和政策快照。
- `AC-ORDER-001-03`：订单号对用户可见，内部 UUID 不作为主要识别信息。

### `REQ-PAY-001` 支付与状态恢复

用户可发起对应平台支付，并在回跳失败或网络中断后恢复最终状态。

- `AC-PAY-001-01`：客户端支付 SDK 返回成功不直接把订单写成已支付。
- `AC-PAY-001-02`：支付回调重复或乱序不会重复入账。
- `AC-PAY-001-03`：未知状态显示“正在确认”，提供订单查询而不是再次支付。

### `REQ-FULFILL-001` 履约跟踪

用户和运营人员能看到接单、出发、开始、完成与异常事件。

- `AC-FULFILL-001-01`：每次状态变化记录时间、操作者和来源。
- `AC-FULFILL-001-02`：通知失败不影响订单事实，应用内仍能查询。

### `REQ-AFTER-001` 取消、退款与售后

系统按政策计算是否可取消、预计退款和处理路径。

- `AC-AFTER-001-01`：确认前显示退款金额、手续费和预计到账时间。
- `AC-AFTER-001-02`：服务已开始时改为售后申请，不伪装成取消成功。
- `AC-AFTER-001-03`：退款状态可查询并与支付流水对应。

### `REQ-REVIEW-001` 服务评价

完成订单的用户能提交评分和评价，未完成或非本人订单不得评价。

- `AC-REVIEW-001-01`：同一订单只允许一条有效评价，允许在期限内编辑。
- `AC-REVIEW-001-02`：评价失败保留输入内容并可重试。

### `REQ-ADMIN-001` 运营订单管理

运营角色能分页筛选订单并进入独立详情页处理问题。

- `AC-ADMIN-001-01`：列表使用中文业务标题和状态，不以内部编号代替说明。
- `AC-ADMIN-001-02`：订单详情包含返回列表按钮并保留筛选条件。
- `AC-ADMIN-001-03`：个人信息默认脱敏，完整查看必须有权限和审计。

### `REQ-ADMIN-002` 服务与价格管理

运营能创建草稿、发布/下架服务和设置未来价格。

- `AC-ADMIN-002-01`：历史订单保持原价格与政策快照。
- `AC-ADMIN-002-02`：存在历史订单的服务只下架，不物理删除。

### `REQ-ADMIN-003` 权限与审计

管理员能为角色分配最小权限，高风险操作必须可审计。

- `AC-ADMIN-003-01`：退款、价格和权限变更记录前后值与原因。
- `AC-ADMIN-003-02`：无权限返回 403，不用前端隐藏代替后端授权。

## 非功能需求

| ID | 要求 | 验收口径 |
|---|---|---|
| `NFR-SEC-001` | 隐私与授权 | PII 默认脱敏；敏感查看和变更均审计；传输和静态数据加密 |
| `NFR-REL-001` | 一致性与可靠性 | 订单/支付写操作幂等；支付最终状态可对账恢复 |
| `NFR-PERF-001` | 性能 | 服务列表 P95 ≤ 800ms；创建订单 P95 ≤ 1.5s，不含第三方支付 |
| `NFR-ACC-001` | 无障碍 | 移动端支持 VoiceOver/TalkBack 与最大字体；后台键盘全流程可完成 |
| `NFR-COMP-001` | 平台兼容 | 小程序最低基础库、iOS/Android 支持范围和后台浏览器矩阵分别验证 |
| `NFR-OBS-001` | 可观测性 | 订单、支付、退款以 traceId 关联日志、指标和审计事件 |
