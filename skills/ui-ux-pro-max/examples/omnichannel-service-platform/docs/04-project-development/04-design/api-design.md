## 资源与命令

- `services` 是可查询资源。
- `availability` 是短期库存视图，不是预约承诺。
- `orders` 是预约与成交快照事实。
- `payments` 和 `cancellations` 是具有独立生命周期的子资源。
- 后台查询使用 `/v1/admin/*`，写操作仍落到所属领域。

## 统一错误

```json
{
  "code": "SLOT_UNAVAILABLE",
  "message": "该时间刚刚被预约，请选择其他时间",
  "traceId": "01J...",
  "details": [{"field": "slotId", "reason": "not_available"}]
}
```

`code` 供程序判断，`message` 可直接展示，`details` 支持字段定位，`traceId` 用于支持与排障。

## 状态码

| 状态码 | 用途 |
|---|---|
| 200 | 查询成功 |
| 201 | 资源创建成功 |
| 202 | 长流程已受理但未最终完成 |
| 400 | 请求格式或查询不合法 |
| 401 | 未认证或会话失效 |
| 403 | 已认证但无权限 |
| 404 | 不存在或无权得知其存在 |
| 409 | 幂等冲突、库存冲突或状态冲突 |
| 422 | 格式正确但违反业务规则 |
| 429 | 超过调用频率 |

## 分页与兼容

- 消费者服务列表和后台大列表使用不透明游标。
- 新增可选字段属于兼容变更；删除、改名、改变类型必须升版本并提供迁移窗口。
- 枚举消费者必须容忍未知值并显示通用状态，不能崩溃。
- 支付和订单事件 schema 必须向后兼容，旧事件可以重放。
