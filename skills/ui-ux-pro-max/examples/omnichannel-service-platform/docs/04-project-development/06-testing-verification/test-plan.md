## 目标与范围

验证服务发现、预约、订单、支付恢复、履约、取消退款、评价和后台运营在四端的业务一致性。重点保护资金、库存、隐私和权限边界。

不在本样例执行真实银行卡/微信扣款、应用商店审核、生产压测或真实用户研究；这些必须在有实现和授权环境后单独执行。

## 测试层次

| 层次 | 责任 | 重点 |
|---|---|---|
| 单元测试 | 研发 | 价格、取消规则、状态机、权限判断、幂等键 |
| 组件/契约测试 | 研发 | OpenAPI 请求响应、错误码、支付/通知适配器 |
| 集成测试 | 研发与测试 | 数据库事务、库存并发、回调乱序、退款对账 |
| UI 自动化 | 各端研发 | P0 流程、返回/恢复、加载/空/错/权限状态 |
| 端到端测试 | 测试 | 从服务发现到履约/售后和后台处理的闭环 |
| 非功能测试 | 专项负责人 | 性能、安全、无障碍、兼容性、可观测性 |

## 环境与测试数据

| 环境 | 用途 | 数据 |
|---|---|---|
| 本地/CI | 单元、静态、契约和组件测试 | 每次创建、用后销毁的固定种子 |
| 集成环境 | 数据库、队列、支付沙箱、端到端 | 脱敏合成用户、服务、时段和订单 |
| 预发布 | 发布候选、性能、安全、回滚演练 | 生产结构的合成数据，禁止复制真实 PII |

测试身份至少包括消费者、客服、运营、管理员和无权限账户。支付使用沙箱成功、失败、超时、重复回调和乱序回调场景。

## 入口与退出门禁

入口：

- PRD、OpenAPI、数据与 UI 设计版本固定；
- 候选构建可部署，迁移和回滚脚本可用；
- 测试环境、沙箱依赖和数据已就绪。

退出：

- P0/P1 用例全部执行，P0 失败为零；
- 订单、支付、退款、授权和隐私相关用例全部通过；
- 性能、安全、无障碍和兼容性达到 NFR 或获得有期限的书面风险接受；
- 报告包含构建、环境、执行时间、失败证据和发布建议。

## 缺陷等级

| 等级 | 定义 | 发布规则 |
|---|---|---|
| P0 | 资金错误、越权、数据损坏、核心流程不可用 | 阻断发布 |
| P1 | 核心流程有高影响故障且无可靠替代 | 默认阻断 |
| P2 | 局部功能或体验错误，有明确替代路径 | 评估后发布 |
| P3 | 文案、轻微视觉或低频问题 | 可进入后续迭代 |
