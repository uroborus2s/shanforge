## 发布前

1. 确认构建来自已批准提交，制品摘要与流水线一致。
2. 确认 [测试报告](../06-testing-verification/test-report.md) 为 GO，P0 缺陷为零。
3. 检查数据库迁移向后兼容、备份可用、回滚已演练。
4. 检查密钥只从密钥管理服务注入，不进入仓库或日志。
5. 检查支付回调、通知、对象存储、队列和观测依赖。
6. 发布窗口内冻结无关变更并通知值守人员。

## 发布顺序

1. 部署向后兼容的数据迁移。
2. 部署后端小流量实例，执行健康、鉴权、服务查询和订单读取探针。
3. 逐步扩大后端流量，观察错误率、延迟、队列和资金对账。
4. 发布管理后台；再提交小程序和移动端，保持服务端兼容旧客户端。
5. 开启功能开关并按渠道、区域或账户逐步放量。

## 发布后验证

| 场景 | 证据 |
|---|---|
| 登录与授权 | 有权限成功、无权限 403、审计事件 |
| 服务发现 | 可售服务正确，空/错误态可恢复 |
| 订单 | 创建幂等、库存扣减与订单事件一致 |
| 支付 | 沙箱或批准的小额验证、回调、对账一致 |
| 后台 | 筛选、详情返回、PII 脱敏与高风险授权 |
| 观测 | traceId 串联 API、队列、支付和审计 |

## 失败处理

超过门禁立即停止扩流并执行 [回滚计划](../07-release-delivery/rollback-plan.md)。不得在没有证据时反复重试迁移或支付回调。
