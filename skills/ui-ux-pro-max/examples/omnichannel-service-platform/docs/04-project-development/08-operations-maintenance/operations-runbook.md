## 服务目标与观测

| 信号 | 关注内容 | 关联要求 |
|---|---|---|
| 流量 | 各渠道 API 请求、订单和支付量 | `NFR-OBS-001` |
| 错误 | 5xx、业务冲突、支付/退款失败、越权尝试 | `NFR-REL-001`、`NFR-SEC-001` |
| 延迟 | 服务列表、订单创建、支付状态查询 P50/P95/P99 | `NFR-PERF-001` |
| 饱和 | 数据库连接、队列积压、线程/协程、第三方限流 | `NFR-REL-001` |
| 业务不变量 | 库存负数、重复入账、订单与支付状态差异 | `REQ-ORDER-001`、`REQ-PAY-001` |

所有订单、支付和退款日志使用 `traceId`、业务订单号和脱敏账户标识；禁止记录完整手机号、地址、支付凭据或令牌。

## 事件分级

| 级别 | 示例 | 首要动作 |
|---|---|---|
| SEV-1 | 重复扣款、广泛越权、订单数据损坏 | 立即停止相关写路径，启动事件指挥与对账 |
| SEV-2 | 核心预约/支付大面积失败 | 停止扩流，启用降级或回滚 |
| SEV-3 | 单一渠道或局部功能退化 | 限定影响范围，安排修复并持续观察 |

## 常见处置

### 支付已扣款但订单显示待支付

1. 用业务订单号查询订单、支付意图、回调事件和第三方交易。
2. 检查回调签名、幂等记录、队列积压和状态机拒绝原因。
3. 若第三方已成功，走受审计的对账补偿；不得让用户重复付款。
4. 记录受影响范围并验证补偿后状态。

### 库存冲突或重复订单升高

1. 查看创建订单的幂等键命中率、库存锁冲突和客户端重试。
2. 判断是正常并发、超时重试还是幂等存储异常。
3. 必要时限制新订单写入，保留查询和用户恢复能力。
4. 检查是否存在负库存或重复收费；存在则升级 SEV-1。

### 后台疑似越权

1. 保留请求、角色、数据范围和审计证据，立即撤销可疑会话。
2. 禁用相关高风险权限或功能开关，不删除审计记录。
3. 判断影响的个人数据和操作范围，按安全事件流程升级。

## 恢复后

- 对账订单、支付、退款、库存和审计数据；
- 完成时间线、根因、影响、修复、验证和预防项；
- 把长期有效的处置更新到本文档版本历史；
- 临时事件记录保存在事件系统，不把每日记录堆入正式 `docs/`。
