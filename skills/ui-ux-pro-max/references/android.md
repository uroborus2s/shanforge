# Android 设计

## 适用范围

Android 手机、平板、折叠屏、桌面窗口，以及 Jetpack Compose 或传统 View。以当前 Material Design、Android 无障碍和目标 API 行为为准。

## 布局与系统区域

- 使用 dp/sp 和语义 token；支持系统字体缩放，不用固定高度截断文本。
- 正确处理状态栏、导航栏、手势区、显示 cutout、IME/键盘和 edge-to-edge insets。
- 使用窗口尺寸和可用空间做自适应；不要按设备名称硬编码手机/平板。
- 大屏和折叠屏考虑列表-详情、导航栏/抽屉、支撑态、铰链/遮挡区和窗口连续缩放。

## 导航与系统行为

- 明确应用内 Up 与系统 Back 的区别；支持系统返回和适用的预测返回体验。
- 导航栏、导航轨、抽屉和双栏布局随空间与任务变化，不只放大底部导航。
- 外部 intent、通知、深链、权限和配置变化后恢复正确上下文。
- 破坏性操作支持撤销或确认；后台任务、前台服务和系统限制要有用户可理解的反馈。

## 组件与输入

- 优先 Material/平台组件和语义；自定义 Compose/View 必须补齐 role、state、content description 和焦点行为。
- 触控目标通常至少 48×48 dp；图标视觉尺寸可小于命中区域。
- 同时支持 TalkBack、Switch Access、键盘、鼠标、触控板和 stylus 中产品声明支持的方式。
- 键盘、指针、hover 和右键不能只是桌面模式补丁；焦点顺序与可见性必须设计。

## 主题与内容

- 使用 Material 语义角色或项目等价 token；动态颜色必须受品牌、对比和状态语义约束。
- 明暗主题分别验证 surface、on-surface、outline、状态层、图表和系统栏。
- 覆盖长文本、最大字体、RTL、复数、本地化数字/日期、窄屏和高对比度。

## 动效

- 采用容器、共享轴、淡入淡出或平台建议的空间转场表达层级。
- 手势动画跟随输入，可中断、可取消；系统 Back 进度与页面反馈保持一致。
- “移除动画”设置下保留状态反馈但减少大幅位移、视差和无关循环。
- 在代表性低端设备和高刷新率设备上测量，不以模拟器顺滑代替真机证据。

## 验收

- 覆盖小屏、常规手机、大屏/平板或折叠态、最大字体、RTL、TalkBack、键盘和手势导航。
- 覆盖旋转、窗口缩放、进程重建、深链、通知、权限拒绝、离线和系统返回。
- 记录 API/系统版本、窗口尺寸、密度、输入方式、主题、语言、结果和证据。
