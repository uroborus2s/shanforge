# Apple 平台设计

## 适用范围

iOS、iPadOS、macOS，以及 SwiftUI/UIKit/AppKit 实现。以当前 Apple Human Interface Guidelines 和目标系统版本为准。

## 共同原则

- 复用系统导航、文本样式、控件、菜单、sheet、alert、分享和权限模式。
- 使用 point 和安全区表达界面；不要以某个截图像素作为全部设备基线。
- 支持 Dynamic Type、VoiceOver、Switch Control、Reduce Motion、Increase Contrast、Bold Text 和 Reduce Transparency 中适用的设置。
- 触控目标通常至少 44×44 pt；小图标可以更小，但命中区域不能更小。
- 系统权限前解释价值；拒绝后提供清晰恢复或替代路径。

## iOS

- 保持返回手势、导航栈、tab、sheet 和全屏流程的语义一致。
- 固定操作栏、输入区和浮层避开状态栏、Dynamic Island、Home Indicator 和键盘。
- 破坏性操作使用清晰角色、确认或可撤销反馈；不要把危险操作放成默认主按钮。
- 手势必须跟手、可中断，并提供可见替代；不要接管系统边缘手势。

## iPadOS

- iPad 不是放大的 iPhone。设计多列、侧栏、检查器、工具栏和更宽内容层级。
- 支持分屏、多窗口、Stage Manager、横竖屏和窗口连续缩放。
- 同时考虑触控、指针、键盘焦点、快捷键、拖放和上下文菜单。
- 尺寸变化时保留选中项、编辑状态和导航上下文，避免强制重置到首页。

## macOS

- 使用窗口、标题栏/工具栏、菜单栏、侧栏、检查器、表格、上下文菜单和快捷键的桌面惯例。
- 支持窗口最小尺寸、缩放、多窗口、全屏、拖放、右键、hover、焦点环和菜单命令。
- 桌面信息密度可高于移动端，但文字、分组、可点击区域和键盘顺序仍需清晰。
- 关键命令有菜单项和快捷键提示；不要把全部能力藏进移动式底部导航。

## 动效

- 优先系统转场和可中断 spring；空间方向表达层级和返回。
- Reduce Motion 下用短淡入、溶解、状态高亮或即时变化替代大幅位移、缩放和视差。
- 动画期间保持输入响应。交互式转场必须支持取消并回到一致状态。

## 验收

- iOS 覆盖最小/常规屏、最大 Dynamic Type、深色、横屏、键盘和 VoiceOver 主路径。
- iPadOS 覆盖紧凑与常规宽度、分屏/窗口缩放、键盘、指针和多窗口恢复。
- macOS 覆盖窗口缩放、菜单/快捷键、键盘焦点、VoiceOver、高对比度和多显示器缩放。
