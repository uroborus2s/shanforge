# 设计流程与交付物

## 目录

- 设计顺序

## 设计顺序

1. 明确用户、场景、任务、限制和成功指标。
2. 画出主路径、替代路径、失败恢复和返回/撤销。
3. 建立信息架构、界面清单、状态矩阵和内容优先级。
4. 先低保真验证结构，再形成视觉方向和设计 token。
5. 定义组件、变体、交互、适配、无障碍和动效。
6. 映射到目标平台，记录共同语义与平台专属行为。
7. 交付实现约束、验收矩阵和实际验证证据。

不要先画一张“漂亮首页”再倒推任务流。没有内容、状态和平台约束的视觉稿不能作为完整设计。

## 最小事实包

开始前尽量从用户输入、仓库和现有产品恢复：

- 用户画像、使用环境、核心任务和业务优先级。
- 内容模型、关键数据、权限、空状态和错误来源。
- 页面、路由、窗口、导航层级和外部入口。
- 品牌、语气、资产授权、文案和本地化范围。
- 平台、设备、输入方式、技术栈和性能等级。
- 现有 token、组件、图标、字体和历史设计决定。

对无法获取的事实写明假设。只在不同答案会改变信息架构、品牌方向或平台行为时请求用户决定。

## 核心产物

按任务裁剪，不强制制造全部文档。

### 设计 brief

- 问题、目标用户、核心任务、成功指标。
- 平台、设备、范围、排除项和约束。
- 已知事实、假设、风险和待决问题。

### 用户流与信息架构

- 入口、主路径、分支、失败、恢复、取消和完成。
- 导航层级、返回语义、深链、搜索和跨端接续。
- 每个节点对应界面、弹层、系统页面或外部跳转。

### 界面与状态矩阵

每个界面记录：目的、主操作、次操作、内容优先级、组件、数据依赖、加载、空、错误、离线、权限、禁用、成功、长文案、明暗主题和无障碍状态。

### 设计系统

- 基础 token：颜色、字体、间距、尺寸、圆角、边框、层级、图标、栅格和动效。
- 语义 token：surface、content、action、feedback、focus、selection、danger 等。
- 组件：结构、变体、尺寸、状态、内容规则、行为、键盘/触控语义和平台映射。
- 响应式与自适应：内容重排、导航变化、显示/隐藏、窗口和设备等级。

### 动效规范

使用 [motion.md](motion.md) 的字段。动效稿必须包含静态或 reduced-motion 替代，不能只给视频。

### 实现 handoff

- 页面/组件名称和代码 owner。
- token 与平台变量映射。
- 尺寸、对齐、内容约束、状态和交互条件。
- 资产路径、格式、许可、裁切和密度要求。
- 验收设备、视口、主题、语言、输入方式和测试命令。
- 已知限制、未验证项和可接受降级。

## 评审量表

按严重度输出问题，并定位到界面、组件、状态或行为。

| 级别 | 判断 |
|---|---|
| Critical | 阻断核心任务、安全/隐私风险、无法访问、数据不可恢复或平台审核必然失败 |
| Important | 明显误导、关键状态缺失、主要设备不可用、严重适配/无障碍/性能问题 |
| Minor | 一致性、细节、文案或非关键动效问题，不阻断主要任务 |

每条 finding 包含：证据、影响用户、触发条件、最小修复、验收方法。不要只写“看起来不专业”。

## 交付完整性

- 设计中的每个核心操作都有反馈、失败和恢复。
- 设计系统能追溯到真实组件，不是一组孤立色值。
- 多端产物明确共享与分叉，不把平台差异藏在注释里。
- 图标、字体、图片、Lottie/Rive 等资产有来源和许可。
- 测试记录区分浏览器、模拟器、真机和静态检查。
- 没有做过的研究、测试和指标不得写成已完成。
