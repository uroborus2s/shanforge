# 桌面端设计

## 适用范围

Windows、macOS、Linux 桌面客户端，以及 WinUI、WPF、Avalonia、Uno、JavaFX、Electron、Tauri 等实现。平台原生 reference 仍优先；macOS 还需读取 [apple-platforms.md](apple-platforms.md)。

## 桌面不是放大的移动端

- 以窗口、文档、工作区和多任务为中心，设计最小/常用/最大窗口，而不是固定画布。
- 允许更高信息密度，但通过分组、对齐、层级、可调整面板和渐进披露保持可读。
- 明确标题栏、菜单、工具栏、命令栏、状态栏、侧栏、检查器、tab 和多窗口职责。
- 系统级关闭、最小化、全屏、拖放、文件打开、最近项目和恢复行为必须可预测。

## 输入与命令

- 所有核心功能支持键盘和指针；为高频动作提供菜单命令和符合平台惯例的快捷键。
- 设计 hover、右键、上下文菜单、tooltip、选择、框选、多选、拖放、滚轮和精确编辑。
- 焦点可见且顺序合理；弹窗关闭后焦点回到触发点；复杂表格有单元格/行/列导航规则。
- 不把 icon-only 工具栏作为唯一入口；用 tooltip、菜单或命令面板提供名称和可发现性。

## 窗口与显示

- 定义最小窗口、断点、面板折叠、横向/纵向溢出和内容优先级。
- 支持多显示器、不同缩放比例、窗口跨屏、远程桌面和高对比度。
- 状态持久化需区分窗口尺寸、位置、面板布局、文档状态和用户偏好；异常退出后安全恢复。
- 固定尺寸对话框只用于真正不可调整的短任务，复杂工作流优先可缩放窗口/页面。

## 平台差异

- Windows：核对 Fluent、系统标题栏、导航视图、命令、键盘助记键、高对比度和触控混合输入。
- macOS：核对菜单栏、窗口工具栏、侧栏/检查器、系统快捷键、全屏与多窗口。
- Linux：明确支持的桌面环境和主题；不要假设系统字体、窗口装饰和快捷键完全一致。
- 跨平台框架：共同 token 和业务组件可共享，窗口 chrome、菜单、文件选择、快捷键和无障碍需平台适配。

## 动效与性能

- 桌面动效强调状态、窗口/面板关系和直接操作反馈，避免移动端式全屏滑动滥用。
- hover/selection/focus 反馈快速稳定，不改变周围布局。
- 大表格、图表、画布和多面板布局要在目标数据量、缩放和多窗口场景测量。

## 验收

- 覆盖最小与大窗口、100%/高 DPI、多显示器或等价模拟、键盘全流程、鼠标/触控板、右键和拖放。
- 检查菜单、快捷键、焦点、窗口恢复、文件操作、高对比度、屏幕阅读器和离线/错误状态。
