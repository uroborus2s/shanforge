# 小程序设计

## 适用范围

微信、支付宝、抖音、百度、QQ、京东等宿主小程序，以及 Taro、uni-app 等跨端实现。平台规则、组件和审核要求会变化，执行时必须核对目标平台当前官方文档。

## 先确认宿主差异

- 明确目标宿主、基础库最低版本、账号类型、开放能力、审核限制和隐私要求。
- 明确是否还要发布 H5、React Native 或其他小程序端；跨端框架不能消除宿主能力差异。
- 列出登录、授权、支付、分享、订阅、定位、相机、蓝牙、文件和客服等能力矩阵。
- 对宿主不支持、需要额外资质或行为不同的能力定义降级，不伪造一致体验。

## 导航与生命周期

- 区分主包启动、分包加载、冷启动、热启动、前后台切换和更新提示。
- 明确页面栈、返回、重启、tab、外部二维码/分享入口和宿主关闭行为。
- 系统授权弹窗前先解释用途；拒绝后提供继续使用、再次授权或替代路径。
- 登录态失效、网络切换、宿主回收和支付/分享回跳必须恢复到可理解状态。

## 布局与组件

- 使用目标平台推荐的单位、系统信息和安全区 API；不要把某一宿主的 `rpx` 规则当成所有端通用事实。
- 触控目标按宿主逻辑尺寸和真机命中区域验收。不得把 Web 的 44 CSS px 直接换算成固定 88rpx，并宣称适用于所有屏幕或宿主。
- 适配状态栏、胶囊/标题区、底部手势区、键盘、横屏和刘海设备。
- 优先原生/宿主组件。WebView、原生组件层级、滚动容器、遮罩和输入框可能有合成限制，设计前先核对。
- 避免深层嵌套滚动、过密操作和依赖 hover 的行为；真机触控目标和误触比开发者工具截图更重要。

## 内容、网络与包体

- 首屏只加载核心内容；大型页面、资源和低频能力按分包/懒加载策略设计。
- 为弱网、离线、接口超时、缓存过期、版本不兼容和资源下载失败提供状态。
- 图片、字体、Lottie、视频和 Canvas 动效必须计入包体、内存、解码和首屏预算。
- 长列表采用分页、窗口化或宿主推荐方案；减少高频跨层数据同步和大对象更新。

## 动效

- 微交互优先使用宿主稳定支持的 transform/opacity 或原生动画能力。
- 复杂品牌动效先确认 Lottie/Canvas/视频的基础库支持、包体和低端机表现。
- 页面转场服从宿主导航；不要叠加一套与系统返回方向冲突的全屏动画。
- 动效必须能在低性能设备上降级为短淡入、静态关键帧或无动画状态。

## 验收

- 开发者工具只用于快速检查，不能代替真机。
- 至少覆盖一台 iOS、一台 Android、最低基础库、弱网、拒绝授权、前后台切换和版本更新。
- 跨端项目分别记录各宿主结果；一个端通过不代表所有端通过。
- 检查包体、首屏、页面栈、分享/二维码入口、支付/授权回跳、键盘遮挡、长列表和动效流畅度。
